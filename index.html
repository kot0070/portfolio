01 · Centerpiece

Local LLM benchmark

ADVANCED PROTOTYPE

Public repository local-llm-benchmark

Local Ollama LLM benchmark harness: 24 machine-checkable HOME tasks across 24 model profiles, time-boxed unattended runner with GPU contention/thermal controls, semantic vs strict scoring with paired-bootstrap HOME verdicts, and Markdown/CSV/Excel reports. One published 8-hour Windows/RTX 3070 night-run artifact set is checked in as evidence.

Interview role: open Applied AI Automation here — fixtures, tasks, runner, scoring, reports, and one published night run.

Verified evidence

  • 24 HOME tasks and 24 model profiles.
  • Checked-in night run results/night_20260921-155146: 4190 records, budget_hours 8, NOT_RUN_BUDGET 799 (~19%). Budget-complete, not matrix-complete.
  • Scoring separates semantic and strict quality and can report HOME_WIN, HOME_TIE, and HOME_LOSS with bootstrap confidence intervals. This page does not quote a model ranking from that run.
  • 331 def test_ functions across 30 modules, counted statically. Pass or fail at the pin was not executed, so this is not a green-run claim.

Key tech

  • Python 3.13
  • pytest with a mock Ollama server
  • Ollama HTTP API on 127.0.0.1:11434
  • Windows PowerShell launchers
  • nvidia-smi GPU telemetry
  • SQLite for the HOME-20 readonly check
  • JSONL, CSV, Markdown, and XLSX reports

Honest limitations

  • Maturity is ADVANCED PROTOTYPE, not WORKING APPLICATION and not PRODUCTION.
  • Single machine (RTX 3070 8GB), one night run, no repeats.
  • Not a definitive multi-hardware leaderboard. About 19% of planned away work was NOT_RUN_BUDGET, so the night was budget-complete rather than matrix-complete.
  • Raw results.jsonl is intentionally unpublished. Checked-in evidence is aggregates, CSV, and xlsx.
  • I do not claim pytest greens such as 251 / 286 / 385 at this pin.
  • No CI at the pin, and dependency manifests are absent. Launchers are Windows and Ollama specific, not portable out of the box.
  • LM Studio and Specialists paths are deferred. Open docs PR #1 is not on main.

Bruno AC

WORKING APPLICATION

Private repository bruno-ac-pwa

Offline-first Progressive Web App (static HTML/JS/CSS + service worker) for HVAC/AC contractor estimating: dual-track catalog pricing, Method A sales quoting, job costing, Service Call Journal/payroll planning, and Texas HVAC code-reference-driven BOM generation, deployed via GitHub Pages.

Interview role: offline trade estimating, plus fail-closed domain limits.

Verified evidence

  • Method A quoting fails closed on invalid financial sentinels. It does not turn NaN into $0.
  • Dual-track catalog: Customer Price versus Your Cost, with an Apply lifecycle.
  • Offline shell with an active service worker cache named bruno-ac-v64.
  • Playwright Browser E2E succeeded on the locked pin. GitHub Pages build and deploy also succeeded on that pin.
  • 28 unit-ish test files and 1 Playwright spec are present. Unit pass counts were not auditor-executed. Pin CI runs Playwright E2E, not the full Node unit suite.
  • The code library stores Texas HVAC 2026 baseline summaries and official URLs, not full code text.

Key tech

  • Vanilla HTML, CSS, and JavaScript, no SPA framework
  • Service worker Cache API, runtime cache bruno-ac-v64
  • Web App Manifest
  • localStorage keys under bruno-ac-*
  • Playwright browser end-to-end tests
  • GitHub Actions and GitHub Pages

Honest limitations

  • Service-worker cache docs do not match the runtime. README says bruno-ac-v4, sw.js uses bruno-ac-v64, and BRAND says bruno-ac-v31. That mismatch is a hygiene gap I would fix before public polish, not a strength.
  • Not PRODUCTION, and not a multi-user cloud backend.
  • No Manual J/S/D. The app refuses square-footage-to-tonnage. Commercial Apply stays blocked pending AHJ or design verification.
  • Payroll figures are estimates, not tax software. Catalog prices include estimating placeholders.
  • I do not claim the full Node unit suite is green in permanent pin CI.
  • Proprietary and private. A public demo needs redaction and permission. Job data stays on the device. One-device localStorage can be lost without a backup.

03 · Supporting

Propeller calculator

WORKING APPLICATION

Private repository propeller-calculator

Offline PySide6/SQLite Windows desktop application that ingests multi-source propeller performance/geometry data, interpolates Ct/Cp, solves motor–propeller operating points, and packages a one-file EXE with an AppData working database. Plain: a Windows program (Ukrainian/English) for choosing and comparing propellers with motor/battery settings using a large offline database.

Interview role: desktop engineering product, and evidence-class honesty that transfers to AI judgment.

Verified evidence

  • Pin-consistent counts: 1053 models and 335434 characteristics, from the README, unit-test assertions, and Final_Audit.json. The release-zip database was not re-queried this session.
  • Ct/Cp interpolation carries evidence_class and extrapolation flags. Water, missing-Rm, and frame paths are labeled PARTIAL.
  • Runtime import checks zip-slip and keeps a backup. The working database installs atomically under AppData.
  • A unittest suite and an offscreen Qt harness are present at the pin. Neither was live-run for the fact-lock, and there is no CI.

Key tech

  • Python 3.11+ on Windows
  • PySide6 6.9.1
  • SQLite
  • PyInstaller one-file windowed EXE
  • unittest
  • Ukrainian and English UI, SI and Imperial units

Honest limitations

  • Not PRODUCTION.
  • No live-verified EXE run and no live database count from the release zip in the fact-lock session.
  • No CI workflows, so builds are not CI-green. The EXE has historically been unsigned, with SmartScreen risk. The v3.3.0 release was still a draft.
  • Water mode is not cavitation-accurate marine modeling. Motor-without-Rm and the frame model are simplified PARTIAL paths.
  • Package __version__ is 3.0.0 while product framing is 3.3.0.
  • Third-party dataset redistribution rights are undocumented. The release database is not published here. A legacy tkinter UI remains in the tree and is not what the main entry launches. Open docs PR #1 is not part of the pin.
